# Spec: Discovery UDP, Eleicao e Heartbeat nas Versoes v2

## Objetivo

Reimplementar as versoes v2 para atender as tarefas 01, 02 e 03 do PDF real:

1. Descoberta inicial de Masters via UDP broadcast.
2. Eleicao deterministica do Master pelo Worker.
3. Transicao para TCP com handshake inicial e inicio do loop de heartbeat da Sprint 1.

## Escopo

- Modificar apenas `master_a_v2_0.py` e `worker_a1_v2_0.py`.
- Manter `master_a_v1.0.py` e `worker_a1_v1.0.py` intactos.
- Reutilizar a semantica de heartbeat da Sprint 1 na v2.
- Substituir o fluxo anterior de `QUERY/NO_TASK` da v2.

## Arquitetura

### Descoberta UDP

- O Worker envia um pacote UDP de descoberta para um endereco de broadcast configurado.
- O Master escuta a porta UDP de descoberta e responde por UDP unicast ao IP/porta de origem do Worker.
- O Worker coleta respostas por ate 3 segundos.

### Eleicao

- O Worker armazena temporariamente as respostas validas de discovery.
- O Worker aplica uma regra deterministica identica para todos os processos.
- A implementacao segue o exemplo do enunciado `MASTER_1 < MASTER_2 < MASTER_10`, usando ordenacao por prefixo + sufixo numerico quando houver numero final.

### Handshake TCP

- O Worker abre conexao TCP para o `TCP_HOST/TCP_PORT` do Master eleito.
- O Worker envia um payload `ELECTION_CONFIRM`.
- O Master valida e responde com `ACK`.

### Heartbeat

- Depois do `ACK`, o Worker entra no loop de heartbeat da Sprint 1.
- Cada heartbeat abre uma conexao TCP curta, envia `TASK=HEARTBEAT` e espera `RESPONSE=ALIVE`.

## Contratos de Mensagem

### Discovery UDP do Worker

```json
{
  "TASK": "DISCOVER_MASTER",
  "WORKER_UUID": "W-123"
}
```

### Resposta UDP do Master

```json
{
  "TASK": "DISCOVERY_RESPONSE",
  "SERVER_UUID": "MASTER_1",
  "TCP_HOST": "127.0.0.1",
  "TCP_PORT": 8000
}
```

### Confirmacao TCP de eleicao

```json
{
  "TASK": "ELECTION_CONFIRM",
  "WORKER_UUID": "W-123",
  "SERVER_UUID": "MASTER_1"
}
```

### ACK TCP do Master

```json
{
  "STATUS": "ACK",
  "SERVER_UUID": "MASTER_1"
}
```

### Heartbeat do Worker

```json
{
  "SERVER_UUID": "MASTER_1",
  "TASK": "HEARTBEAT"
}
```

### Resposta de heartbeat do Master

```json
{
  "SERVER_UUID": "MASTER_1",
  "TASK": "HEARTBEAT",
  "RESPONSE": "ALIVE"
}
```

## Criterios de Aceite

- O Worker descobre Masters sem IP TCP previamente configurado.
- O Worker coleta respostas por ate 3 segundos.
- O Worker aplica a eleicao deterministica e escolhe um Master.
- O Worker confirma a eleicao por TCP e recebe `ACK`.
- O Worker inicia o loop de heartbeat com o Master eleito.
- As versoes v1 permanecem intactas.
